## 5. Contract changes the dashboards must absorb

All documented in `specs/web-dashboard-endpoints.md` §5a/§5b and §6.

1. **Errors** are `{ code, message, details? }` — no `{ success:false, error }` envelope.
2. **Every list** returns `{ data, meta: { total, page, limit, totalPages } }`; `?page` ≥ 1, `?limit` 1–100; unknown enum filters are `400`, not `500`.
3. **`PATCH /orders/:id/cancel`** cancels the whole checkout group and returns `cancelledOrderIds`.
4. **Vendor `category`** is an enum (`FASHION | FOOD | HOME_CRAFTS | BEAUTY | ACCESSORIES | KIDS | ART | OTHER`) on register, profile and search.
5. **Ratings:** `orderId` optional; required for VENDOR/PRODUCT, absent for BAZAAR.
6. **`POST /auth/register`** creates SHOPPER only; `role` may be omitted or `SHOPPER`.
7. **Rate limits:** 300/min per user (per IP anonymous), 10/min on login/register, 1/min on location updates → `429 RATE_LIMITED` + `Retry-After`.
8. **CORS** allow-list from `CORS_ORIGINS` (defaults to localhost:3000/3001).
9. **Public reads** (`GET /vendors/:id`, `GET /products/:id`) no longer include `ownerId`, `subscriptionStatus`, `rejectionReason`, `isActive`, `deletedAt`.

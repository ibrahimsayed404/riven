## 2. Endpoints

| Method | Path | Returns | Errors |
|---|---|---|---|
| GET | `/admin/orders` | Every order, newest first, as `{ data, meta }`. Filters: `status?`, `vendorId?`, `userId?`, `orderGroupId?`, `page`, `limit`. Each row embeds `vendor { id, name }` and `user { id, name, email }`, **without items**. | 400 on a bad enum, a non-uuid id or an unknown query field |
| GET | `/admin/orders/:id` | Any order, plus `items` (purchase-time snapshots) and `orderGroup { id, createdAt, paidAt, paidAmountCents, paymobOrderId, paymobIntentId, paymobTransactionId }` | 404 `ORDER_NOT_FOUND` (an existing code, reused) |

**The Paymob ids appear on this admin route only.** The shopper's `GET /orders/:id` still doesn't include `orderGroup`, and the e2e suite checks that.

Both routes have class-level `JwtAuthGuard` and `RolesGuard` with `@Roles(Role.ADMIN)`. They are reads, so no audit rows are written. The list uses the module's existing `$transaction([count, findMany])` pattern, so `meta.total` matches the page. Relations are loaded through one `include`, so there is no N+1.

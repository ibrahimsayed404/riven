## 3. Design notes

- **One visibility rule for bazaars** (`bazaars/bazaar-visibility.ts`), mirroring `PUBLIC_PRODUCT_WHERE`. It's applied at all seven places that decided visibility before:
  - `findPublicPaginated` and `findNearby` use a correlated `EXISTS` on organizers, so the selected columns are unchanged.
  - `listPublicIds` and `isRateable` use a Prisma relation filter.
  - `findPublicById`, `getSearchDocument` and `applyToBazaar` call a new `hasPublicOrganizer`.

  `findById` itself was **not** changed, because it also feeds owner routes, whose response shape must stay the same.
- **New search fan-out `ORGANIZER_BAZAARS`.** It's enqueued when an organizer's `verified` flips, and on organizer soft delete; a reason-only change doesn't enqueue it. It mirrors `VENDOR_PRODUCTS`.
- **`common/changed-fields.ts`** is shared by the vendor and product edits. It's typed by the *update* object, so it can only ever return fields the admin DTO allows.
- **Allow-lists enforced three ways:**
  - DTOs built with `PickType` from the owner DTOs (the same validators)
  - the whitelist pipe (any other field → 400)
  - `ProductsRepository.updateContentForAdmin`, whose parameter type **is** the allow-list
- **Guarded application transition** (`updateMany where status = PENDING`, count check). A concurrent organizer decision can't be overwritten. The organizer's own path still has the old unguarded update (follow-up §6).
- **New modules wired to `AuditModule`:** social, orders, booths and search.

- **Doc fixes:**
